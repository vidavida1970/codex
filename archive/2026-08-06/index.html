핵심 개념 1분

회귀 테스트는 새 프롬프트가 더 그럴듯한지 감으로 보는 작업이 아닙니다. 고정된 대표 입력과 같은 평가표로 v1·v2를 비교해, 품질이 유지되는지 확인하는 작업입니다.

입력고정 테스트셋정상 2개, 예외 1개, 누락 1개처럼 바꾸지 않는 입력을 둡니다.
기준평가기준과 통과 조건근거·대상 적합성·형식·금지 표현처럼 합격선을 먼저 적습니다.
비교v1 vs v2 동시 판정같은 입력·같은 기준으로 통과/실패를 표에 기록합니다.
판정회귀·개선·보류기존 통과 케이스가 다시 실패하면 배포하지 않습니다.

사실과 강사 해석

확인된 사실: OpenAI Cookbook은 analyze → measure → improve 순환과 테스트 데이터셋·grader 사용을 권합니다. Working with evals 가이드도 지정한 스타일·내용 기준으로 출력을 평가하고 프롬프트를 반복 개선하라고 안내합니다.

강사 해석: 애드아이티 템플릿도 같은 방식으로 운영할 수 있습니다. 정상·예외·누락 입력을 고정하고, 통과 조건을 먼저 적은 뒤 v2를 같은 표로 재시험하세요. 국내의 프롬프트 회귀 테스트 성과를 수치로 입증한 공개 실무 사례는 확인하지 못해 꾸며 넣지 않았습니다.

2분 따라 하기

  1. DAY 18 템플릿 v1과 DAY 19 프롬프트 v2를 준비합니다.
  2. 정상 2개, 예외 1개, 누락 1개 입력을 고정합니다.
  3. 평가기준 3~4개와 통과 조건을 적습니다.
  4. 같은 입력으로 v1·v2를 실행하고 통과/실패를 표로 기록합니다.

복사형 실전 프롬프트

[역할] 너는 프롬프트 회귀 테스트 담당자다. 새 결과물을 쓰지 말고, 기존 프롬프트 버전들이 고정 테스트셋에서 통과하는지 판정하라. [업무 목적] [누가 무엇을 위해 쓰는 결과물인지] [비교 대상] - 프롬프트 v1: [붙여넣기] - 프롬프트 v2: [붙여넣기] [고정 테스트셋] 1. 정상 입력 A: [입력] 2. 정상 입력 B: [입력] 3. 예외 입력 C: [입력] 4. 누락 입력 D: [입력] [평가기준과 통과 조건] 1. [기준1]: [통과 조건] 2. [기준2]: [통과 조건] 3. [기준3]: [통과 조건] 4. [기준4]: [통과 조건] [수행] 1. 각 테스트 입력마다 v1·v2 출력을 기준별로 통과/실패 판정한다. 2. v1에서 통과했는데 v2에서 실패한 항목을 `회귀`로 표시한다. 3. v1에서 실패했는데 v2에서 통과한 항목을 `개선`으로 표시한다. 4. 판정 이유를 한 줄로만 적는다. 근거 없는 추측은 쓰지 않는다. 5. 최종 권고를 `배포 가능 / 수정 후 재시험 / v1 유지` 중 하나로 고른다. 6. 수정이 필요하면 가장 영향 큰 원인 1개와 최소 수정안만 제안한다. [제약] - 테스트 입력과 평가기준을 임의로 바꾸지 않는다. - 없는 출력 내용을 지어내지 않는다. 실제 출력이 없으면 `실행 결과 필요`라고 표시한다. - 길이 증가를 품질 향상으로 보지 않는다. - 국내외 성과 수치를 추정하지 않는다. [출력 형식] 1) 테스트 결과표 | 입력 | 버전 | 기준1 | 기준2 | 기준3 | 기준4 | 종합 | 비고 | 2) 회귀 목록 3) 개선 목록 4) 최종 권고 5) 최소 수정안 1개

결과 체크 3문항

  • 같은 입력과 같은 평가표로 v1·v2를 비교했는가?
  • 기존 통과 케이스의 재실패(회귀)를 표시했는가?
  • 배포/보류 판단이 테스트 결과와 연결되는가?

자주 하는 실수

  • 마음에 드는 한 결과만 보고 템플릿을 교체하기
  • 테스트 입력까지 바꿔 비교 불가능하게 만들기
  • 정상 입력만 보고 예외·누락 입력을 빼먹기
  • 회귀가 있는데도 “대체로 좋아짐”으로 배포하기

오늘의 미션

애드아이티 업무 템플릿 1개에 대해 고정 테스트셋 4개 + 평가기준 3개로 v1·v2 회귀 테스트표를 완성하세요. 회귀가 1개라도 있으면 배포하지 말고, 원인 1개만 수정한 뒤 같은 표로 다시 시험합니다.

최신 업데이트

평가 기반 프롬프트 개선 공식 문서 확인
