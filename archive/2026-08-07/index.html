사실과 강사 해석

확인된 사실: OpenAI Cookbook은 실패 분석, 테스트 기준 고정, 개선 재측정의 evaluation flywheel을 권합니다. Working with evals 가이드도 지정한 스타일·내용 기준으로 출력을 평가하고 프롬프트를 반복 개선하라고 안내합니다.

강사 해석: 애드아이티 팀도 같은 원리를 사람 검수에 적용할 수 있습니다. DAY 20 기준을 확인 방법·통과 기준·조치·담당 칸으로 펼치면, 개인 감각이 아니라 공통 배포 기준이 됩니다. 국내 팀의 AI 검수 체크리스트 도입 성과를 수치로 입증한 공개 실무 사례는 확인하지 못해 꾸며 넣지 않았습니다.

2분 따라 하기

  1. DAY 20 평가기준 3~4개를 가져옵니다.
  2. 각 기준을 확인 방법 / 통과 기준 / 실패 시 조치 / 담당으로 펼칩니다.
  3. 팀 공통 항목 5~7개로 정리하고 필수 항목을 표시합니다.
  4. 최근 결과물 1개에 적용해 배포 / 보류 / 재작성을 고릅니다.

복사형 실전 프롬프트

[역할] 너는 팀 품질 검수 설계자다. 결과물을 대신 쓰지 말고, 개인 평가기준을 팀 공통 검수 체크리스트로 전환하라. [업무 결과물] - 결과물 유형: [제안 요약문 / SNS 초안 / 브리핑 / 기타] - 사용처: [누가 어디에 쓰는가] - 독자: [최종 독자] - 위험 요소: [과장, 미확인 수치, 개인정보 등] [기존 평가기준 또는 회귀 테스트표] [DAY 20 표 또는 기준 붙여넣기] [샘플 결과물] [검수할 초안 붙여넣기] [수행] 1. 팀 공통 검수 항목 5~7개를 만든다. 2. 각 항목에 아래 4칸을 채운다. - 확인 방법 - 통과 기준 - 실패 시 조치 - 담당(작성자/1차 검수/최종 승인) 3. 필수 항목과 선택 항목을 구분한다. 4. 샘플 결과물에 체크리스트를 적용해 항목별 통과/실패를 판정한다. 5. 최종 판정을 `배포 / 보류 / 재작성` 중 하나로 고르고 이유를 2줄 이내로 적는다. 6. 실패 항목이 있으면 수정 요청 문장 1줄과 재검수 포인트를 제시한다. [제약] - 확인되지 않은 성과 수치를 만들지 않는다. - 주관적 표현(“더 멋지게”, “좀 부드럽게”)만으로 판정하지 않는다. - 없는 원문 내용을 있다고 쓰지 않는다. - 체크리스트를 10개를 넘기지 않는다. 실무에서 2분 안에 돌릴 수 있어야 한다. [출력 형식] 1) 팀 검수 체크리스트 표 | 순번 | 항목 | 필수여부 | 확인 방법 | 통과 기준 | 실패 시 조치 | 담당 | 2) 샘플 결과물 검수 결과 | 항목 | 결과 | 근거 한 줄 | 3) 최종 판정 4) 수정 요청 문장 5) 다음 회차 개선 백로그 후보 1개

결과 체크 3문항

  • 평가기준이 확인 방법·통과 기준·조치·담당까지 펼쳐졌는가?
  • 다른 팀원이 같은 표로 같은 판정을 내릴 수 있는가?
  • 최종 판정이 배포/보류/재작성 중 하나로 남는가?

자주 하는 실수

  • “전체 느낌” 칸만 두고 세부 합격선을 비우기
  • 확인 방법 없이 통과/실패만 동그라미 치기
  • 실패해도 조치와 담당이 없어 책임이 흐려지기
  • 체크리스트가 너무 길어 실무에서 쓰이지 않기
