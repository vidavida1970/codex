핵심 개념 1분

출처 충돌은 정답 찾기보다 비교 조건 맞추기에서 시작합니다. 숫자가 다르다고 하나가 곧 거짓인 것은 아닙니다. 같은 단어가 다른 분모·기간·대상을 뜻할 수 있습니다.

CLAIM주장두 자료가 실제로 같은 질문과 지표에 답하는지 확인합니다.
DEFINE정의조회·도달·참여, 전체·순증가처럼 지표와 분모를 맞춥니다.
TIME시점발행일과 측정기간, 공포일과 시행일을 분리합니다.
SCOPE범위·방법지역·표본·채널·유료 포함 여부와 조사·행정·추정 방식을 비교합니다.
SOURCE권위·독립성1차 자료인지, 수정판인지, 여러 보도가 같은 원문을 재인용한 것인지 봅니다.

오늘의 실제 사례

Stanford 연구 사례 · 2026.02.17

검증은 검색량보다 선별된 근거의 품질이 좌우했다

기관Stanford Tech Impact and Policy Center 및 공동 연구진문제상충하거나 미묘한 정치적 주장에 대해 AI가 전문 팩트체커의 판정을 재현할 수 있는지 검증업무 흐름15개 모델을 PolitiFact가 18년에 걸쳐 검증한 6,000개 이상 주장에 적용하고, 기본 지식·추론·웹 검색·선별된 근거 제공 조건을 비교했습니다.실제 결과Stanford 요약에 따르면 선별 근거 제공 시 모델 변형 전체의 성능이 평균 233% 향상됐고, 최고 구성의 macro F1은 0.27에서 0.90으로 올랐습니다. 연구진이 보고한 실험 결과이며 실무 현장 성과는 아닙니다.재현 포인트검색 결과를 많이 모으는 대신 승인된 1차 자료와 신뢰할 수 있는 독립 검증 자료를 먼저 묶고 동일한 판정표로 비교합니다.

내 업무 적용 포인트

ChatGPT에게 먼저 결론을 묻지 말고 승인 근거 묶음 + 충돌 판정표를 제공합니다. 공개 검색은 누락 확인에 쓰고 최종 채택은 사람이 검수합니다.

2분 따라 하기

  1. 제안서에서 서로 다른 수치가 붙은 주장 1개를 고릅니다.
  2. 두 원문에서 정확한 문장·표·측정기간을 복사합니다.
  3. 주장·정의·분모·시점·범위·방법·출처 독립성을 2행 표로 맞춥니다.
  4. 충돌 원인을 한 문장으로 쓰고 채택·범위 병기·보류 중 하나를 결정합니다.

복사형 실전 프롬프트

[역할] 너는 공공기관 제안서의 근거 충돌 검증자다. [입력] - 검증할 주장: [문장] - 출처 A: [원문/URL] - 출처 B: [원문/URL] - 사용 목적과 기준 시점: [제안서 목적/날짜] [규칙] 1. 두 출처가 같은 주장을 다루는지 먼저 확인한다. 2. 지표 정의·분모·단위·측정기간·대상·지역·표본·방법을 분리한다. 3. 발행일과 실제 측정일·시행일을 혼동하지 않는다. 4. 출처가 같은 원자료를 재인용하면 독립 근거로 세지 않는다. 5. 다수결, 단순 최신순, 서로 다른 수치의 평균으로 결론내리지 않는다. 6. 1차 자료라도 사용 목적과 범위가 다르면 자동 우선하지 않는다. 7. 확인하지 못한 정보는 추측하지 말고 ‘검증 필요’로 표시한다. [출력] 출처 | 정확한 주장 | 정의·분모 | 측정기간 | 범위·표본 | 방법 | 원자료·독립성 | 한계 - 충돌 원인 1문장 - 판정: 채택 / 범위 병기 / 보류 / 제외 - 판정 근거 - 추가 확인 자료·담당자·기한 - 제안서에 넣을 안전한 최종 문장

결과 체크 3문항

  • 두 출처가 같은 지표·분모·측정기간을 말하는지 확인했는가?
  • 여러 링크가 같은 원자료를 재인용한 것인지 구분했는가?
  • 해결하지 못한 충돌을 숨기지 않고 범위 또는 검증 과제로 남겼는가?

자주 하는 실수

  • 검색 결과 수가 많은 쪽을 사실로 정하는 것
  • 발행일이 최신이면 측정자료도 최신이라고 생각하는 것
  • ‘조회·도달·참여’처럼 정의가 다른 지표를 한 숫자로 합치는 것
  • ChatGPT의 자신감 있는 판정을 검증 결과로 착각하는 것
