핵심 개념 1분

Project는 공용 맥락, chat은 하나의 산출물입니다. 장기 업무의 자료와 규칙은 Project에 고정하고, 요구사항표·전략안·원고·검수표는 서로 다른 chat에서 완성하세요.

SCOPE업무 범위기관·사업·기준일이 보이는 이름을 붙입니다.
SOURCES공식 자료최신 RFP·브랜드 가이드·승인 사례만 올리고 구버전을 표시합니다.
RULES프로젝트 지침출처 우선순위·금지사항·출력·검수 기준을 고정합니다.
CHATS산출물별 chat요구사항 분석, 전략, 원고, 검수를 각각 분리합니다.

복사형 실전 프롬프트

[이 Project의 목적] [기관명]의 [사업명] 제안 업무를 근거 기반으로 완성한다. [자료 규칙] 1. 먼저 파일명·작성기관·기준일·버전·용도를 표로 정리한다. 2. 최신 버전만 기준으로 삼고, 충돌·구버전·누락은 작업 전에 보고한다. 3. 중요한 주장과 수치는 파일명과 페이지·표·행 위치를 붙인다. 4. 자료에 없는 사실·수치·사례를 만들지 않는다. [작업 규칙] - 사실·추론·제안을 구분한다. - chat마다 하나의 산출물과 완료 기준을 먼저 확인한다. - 정보가 부족하면 추정하지 말고 확인 질문 목록을 만든다. [출력 규칙] 결론 먼저, 짧은 문단과 표를 사용한다. 마지막에 누락·근거·형식 체크 3문항으로 자체 검수한다. [첫 작업] 현재 Project sources의 자료 인벤토리와 위험·누락을 먼저 보여줘.

결과 체크 3문항

  • Project sources에 최신·승인 자료만 있고 기준일이 보이는가?
  • 프로젝트 지침에 근거·금지·출력·검수 규칙이 모두 있는가?
  • 각 chat이 하나의 산출물과 완료 기준만 다루는가?

자주 하는 실수

  • 구버전과 최신 파일을 같은 이름으로 함께 올리는 것
  • Project 하나에 여러 기관·사업을 섞는 것
  • 모든 산출물을 끝없는 한 chat에서 만드는 것
  • 공유 전 자료 권한과 참여자 접근 범위를 확인하지 않는 것

확인된 사실: OpenAI는 Projects를 장기 업무의 chat·파일·프로젝트 지침을 한곳에 유지하는 작업공간으로 안내합니다. 공유 Project는 참여자가 같은 자료와 지침을 바탕으로 이어서 작업하는 맥락 허브이며, 공유 시 project-only memory가 적용됩니다.

실무 해석: 제안서의 공통 근거와 규칙은 Project에, 개별 산출물은 별도 chat에 두면 버전 혼선을 줄일 수 있습니다.

강사 제안: 공유 전 민감정보·업로드 권한·edit/chat 접근 수준을 확인하세요.
