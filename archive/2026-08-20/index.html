오늘의 학습목표
개인 메모리·project-only memory·프로젝트 지침을 구분해 제안 업무의 맥락은 이어가고, 사업별 규칙은 섞이지 않게 설계한다.

핵심 개념 1분

기억은 맥락을 이어가고, 지침은 결과의 기준을 고정합니다. 계정 전반의 선호는 개인 메모리, 한 사업의 대화 맥락은 project-only memory, 반드시 지킬 작업 규칙은 프로젝트 지침에 둡니다.

PERSONAL
MEMORY계정 전반의 안정된 선호답변 언어·상시 선호처럼 여러 대화에 반복 적용할 정보입니다.
PROJECT-ONLY
MEMORY한 Project 안의 업무 맥락같은 Project의 대화끼리 맥락을 활용하고, 바깥 대화와의 참조를 차단합니다.
PROJECT
INSTRUCTIONS명시적인 작업 기준출처 우선순위·문체·금지사항·출력 형식·검수 기준을 고정합니다.
PROJECT
SOURCES검증 가능한 근거RFP·브랜드 가이드·승인본처럼 답변의 사실 근거가 되는 파일입니다.

내 업무 적용 포인트

“기억해”라고 쓰기 전에 그 정보가 계정 전체·이 Project·작업 규칙·근거 자료 중 어디에 속하는지 먼저 결정하세요.

2분 따라 하기

  1. 진행 중인 제안 Project의 메뉴에서 Project settings를 엽니다.
  2. 사업 맥락을 다른 대화와 분리해야 한다면 Project-only memory를 선택합니다.
  3. 프로젝트 지침에 근거·문체·금지·출력·검수 기준을 5줄로 씁니다.
  4. 아래 프롬프트로 현재 정보의 저장 위치를 점검합니다.

복사형 실전 프롬프트

이 Project의 현재 정보와 규칙을 다음 4가지로 분류해줘. 1. 개인 메모리 후보: 여러 업무에 오래 적용할 선호 2. Project 맥락: 이 사업의 대화에서만 이어갈 정보 3. 프로젝트 지침: 반드시 지켜야 할 명시 규칙 4. Project source: 원문으로 확인해야 할 근거 자료 각 항목을 [내용 / 위치 / 이유 / 위험 / 조치] 표로 작성해. 검수 규칙: - 개인정보·다른 기관의 비공개 정보는 저장 후보에서 제외 - 사실과 작업 규칙을 섞지 않기 - 오래된 내용은 기준일과 확인 필요 표시 - 확실하지 않은 내용은 임의로 기억시키지 말고 질문으로 남기기 마지막에 지금 바로 옮기거나 삭제할 항목 3개를 우선순위로 제안해.

결과 체크 3문항

  • 계정 전반의 선호와 사업 전용 정보가 분리됐는가?
  • 프로젝트 지침이 기억에 맡기지 않고 문장으로 명시됐는가?
  • 개인정보·다른 기관 자료·오래된 사실의 위험을 확인했는가?

자주 하는 실수

  • 모든 규칙을 “기억해” 한마디로 처리하는 것
  • project-only memory를 보안·권한 검토의 대체물로 보는 것
  • Project memory에 별도 목록이 있다고 가정하는 것
  • 설정 변경이 즉시 반영된다고 생각하는 것—공식 문서는 몇 시간이 걸릴 수 있다고 안내합니다.

최신 업데이트

2026.08.14 · 기존 Project의 메모리 설정 변경

확인된 사실: 이제 적격한 비공유 Project는 생성 후에도 Project settings에서 Default memory와 Project-only memory를 바꿀 수 있습니다. 공유 Project는 계속 project-only memory로 유지되며, 변경 반영에는 몇 시간이 걸릴 수 있습니다.

실무 해석: 이미 운영 중인 기관별 Project도 새로 만들지 않고 정보 경계를 재설계할 수 있습니다.

강사 제안: 변경 후에는 테스트 chat에서 다른 Project의 정보가 섞이지 않는지 확인하고, 민감자료는 별도 권한·보안 기준으로 관리하세요.
