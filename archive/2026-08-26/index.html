DAY 34. Work에서 승인 지점이 있는 실행계획 만들기

앱 연결 후에는 “실행해줘”보다 “어디서 멈추고 승인받을지”를 먼저 설계해야 합니다.

Work에서 앱과 자료를 연결하면 읽기, 초안 작성, 파일 변경, 메시지 발송 같은 일이 한 흐름에 들어옵니다. 실행 전 계획을 받아 승인 지점을 고정해야 결과를 통제할 수 있습니다.

오늘의 목표

연결 앱이 포함된 업무를 SCOPE → READ → DRAFT → REVIEW → ACT → LOG 단계로 나누고, 승인 없이는 실행하지 않을 행동을 명확히 표시합니다.

핵심 개념

SCOPE

자료 경계 먼저 고정읽을 폴더, 문서, 기간, 제외할 자료를 정합니다.

READ

읽기와 실행을 분리검색, 요약, 근거 추출은 자동 진행할 수 있지만 변경·발송과 섞지 않습니다.

DRAFT

초안은 외부 영향 없이메일, 일정, 파일명, 댓글은 먼저 초안과 변경 목록으로 받습니다.

APPROVAL

중요 행동은 승인 후 실행발송, 삭제, 권한 변경, 외부 공유는 사람 확인 뒤 진행합니다.

공식 기준

OpenAI의 Apps in ChatGPT 문서는 앱 권한이 언제 확인을 요청하는지 제어하며, 기본값인 Important actions는 읽기는 자동으로 할 수 있지만 외부 영향·민감 정보·되돌리기 어려운 행동 전에는 확인을 요구한다고 설명합니다.

Workspace Agents 안내도 반복 업무, 앱·도구 연결, 공유와 스케줄 실행을 다루므로 실행계획 안에 승인 지점을 두는 방식이 실무 운영에 맞습니다.

실무 예시

단계요청 예시승인 기준
SCOPE제안 폴더의 8월 RFP와 회의록만 읽기자동 가능
DRAFT고객에게 보낼 확인 메일 초안 작성초안만
REVIEW수신자, 첨부, 민감 정보 포함 여부 표로 확인사람 검토
ACT승인 후 메일 발송 또는 파일 권한 변경명시 승인 후

복사형 실전 프롬프트

너는 Work 실행계획 검수자다. 업무 목표: {무엇을 끝낼지} 연결 앱: {Drive, Gmail, Calendar, GitHub 등} 허용 자료: {읽어도 되는 폴더·문서·기간} 허용 행동: {초안 작성, 요약, 일정 후보 작성 등} 금지 행동: {발송, 삭제, 권한 변경, 외부 공유 등} 승인자: {최종 확인할 사람} 완료 기준: {검수 가능한 산출물} SCOPE, READ, DRAFT, REVIEW, ACT, LOG 단계로 실행계획을 작성해줘. 각 단계마다 위험도, 승인 필요 여부, 중단 조건을 붙여줘. 승인 없이 메일 발송·파일 삭제·권한 변경·외부 공유를 실행하지 마.

체크리스트

  • 읽을 자료와 제외할 자료가 분리되어 있는가?
  • READ 작업과 ACT 작업이 분리되어 있는가?
  • 메일 발송, 파일 삭제, 권한 변경, 외부 공유가 승인 지점에 묶여 있는가?
  • 실행 후 남길 기록과 재사용 방법이 정해져 있는가?

오늘의 미션

연결 앱이 들어가는 업무 하나를 골라 SCOPE → READ → DRAFT → REVIEW → ACT → LOG 실행계획을 작성하고, 승인 없이 실행하면 안 되는 행동 3개를 표시하세요.
