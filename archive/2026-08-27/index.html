DAY 35. 자동화 요청을 정확히 설계하는 법

자동화는 “매일 해줘”가 아니라 “언제, 무엇을 보고, 어떤 조건에서, 어디까지 실행할지”를 정하는 일입니다.

반복 업무를 자동화할 때는 실행 시점, 확인할 소스, 알림 조건, 결과물 형식, 승인 필요 행동을 분리해야 합니다. 이 구조가 있어야 자동화가 편리함을 넘어 검수 가능한 업무 시스템이 됩니다.

오늘의 목표

업무 자동화를 Trigger → Source → Condition → Action → Approval → Output → Stop rule 7칸으로 설계하고, 실행 전 확인해야 할 모호한 조건을 제거합니다.

핵심 개념

TRIGGER

시작 조건정해진 시간, 반복 주기, 특정 이벤트, 변경 감지 중 무엇으로 시작할지 정합니다.

SOURCE

확인 대상문서, 메일, 캘린더, 저장소, 웹페이지처럼 자동화가 확인할 소스를 고정합니다.

CONDITION

알림 기준매번 보고할지, 새 내용이 있을 때만 보고할지, 특정 조건일 때만 실행할지 정합니다.

APPROVAL

승인 지점발송, 삭제, 권한 변경, 외부 공유는 자동 실행보다 승인 후 실행으로 둡니다.

공식 기준으로 보기

OpenAI의 Scheduled tasks in ChatGPT 안내는 ChatGPT가 1회성 작업, 반복 작업, 변경 모니터링, 가능한 경우 이벤트 기반 작업을 지원한다고 설명합니다. Scheduled 페이지에서 작업을 검토하고 일시정지, 재개, 수정, 삭제할 수 있다는 점도 중요합니다.

ChatGPT Work and Codex 안내는 Work가 일정, 트리거, 변경 모니터링을 통해 실행될 수 있고, 사용자가 진행 상황 확인과 중요 행동 승인을 할 수 있다고 설명합니다.

자동화 설계표

항목좋은 작성 예시주의점
Trigger매주 월요일 오전 8시“자주”, “아침쯤”처럼 흐린 표현 피하기
Source지정한 Project 파일 3개와 공식 공지 페이지출처가 넓으면 결과가 흔들림
Condition새 공지가 있거나 마감이 7일 이내일 때만 알림매번 알림인지 조건부 알림인지 구분
Action핵심 변경 5줄과 실행 체크리스트 작성외부 발송·삭제는 Action에 섞지 않기
Approval메일 발송·권한 변경은 승인 후 실행되돌리기 어려운 행동은 자동 실행 금지
Output요약표, 오늘 할 일, 확인 필요 항목결과 형식을 정해야 재사용 가능
Stop rule3회 연속 새 내용이 없으면 일시정지 제안끝나는 조건이 없으면 불필요하게 반복됨

복사형 실전 프롬프트

너는 업무 자동화 설계자다. [자동화 목표] 업무명: {예: 매주 월요일 제안 진행상황 요약} 목적: {왜 자동화하는지} 실행 방식: {1회 / 반복 / 조건 모니터링 / 이벤트 트리거} 실행 시점: {날짜, 시간, 주기, 종료 조건} 확인할 소스: {문서, 메일, 캘린더, 저장소, 웹페이지} 결과물 형식: {요약표, 체크리스트, 초안, 알림} 승인 필요 행동: {발송, 삭제, 권한 변경, 외부 공유 등} 실패 시 처리: {누락, 권한 오류, 결과 없음, 확인 필요} 아래 표로 자동화 설계안을 먼저 작성해줘. 1. Trigger: 언제 또는 어떤 조건에서 시작되는가 2. Source: 무엇을 확인하는가 3. Condition: 어떤 경우에만 알려주는가 4. Action: 무엇을 만들거나 실행하는가 5. Approval: 사람이 확인해야 할 지점은 어디인가 6. Output: 어떤 형식으로 남길 것인가 7. Stop rule: 언제 멈추거나 다시 묻는가 모호한 시간, 출처, 승인 기준이 있으면 자동화를 만들기 전에 질문해줘.

체크리스트

  • 자동화가 1회성, 반복, 조건 모니터링, 이벤트 트리거 중 어디에 해당하는가?
  • 확인할 소스와 제외할 소스가 분명한가?
  • 매번 알림인지, 조건이 충족될 때만 알림인지 정했는가?
  • 발송·삭제·권한 변경·외부 공유가 승인 지점에 묶여 있는가?
  • 결과물 형식과 멈춤 조건이 정해져 있는가?

오늘의 미션

반복 업무 하나를 골라 Trigger, Source, Condition, Action, Approval, Output, Stop rule 7칸 자동화 설계표를 작성하고, 자동화 전에 꼭 물어봐야 할 모호한 조건 2개를 표시하세요.

“자동화는 반복을 줄이는 기술이 아니라, 반복의 기준을 세우는 운영 방식입니다.”
