# DAY 10. 결과 검수의 4단계

> 그럴듯한 답은 납품 가능한 답이 아닙니다. 결과를 믿기 전에 네 번 확인하세요.

## 오늘의 학습목표

ChatGPT 결과를 네 단계로 검수하고, 수정 근거가 남는 결함 로그를 완성한다.

## 핵심 개념 1분

1. **요구 일치** — 목적·대상·필수 항목·제약·완료 기준 확인
2. **근거 검증** — 수치·날짜·인용·링크를 원자료와 대조하고 사실·추론·제안 구분
3. **논리·실행성** — 주장과 근거의 연결, 담당자·일정·자원·위험 확인
4. **형식·표현** — 분량·구조·용어·가독성·공공기관 문체·보안 확인

검수는 심각도·정확한 위치·판단 근거·수정안·미해결 질문이 있는 결함 로그로 남긴다. 결함을 먼저 승인한 뒤 수정한다.

## 잘못된 사용법과 개선

- 잘못된 요청: “완벽한지 검토하고 알아서 수정해줘.”
- 개선: 네 관문별 결함표를 먼저 작성하고 멈춘다. 치명·중요·경미를 구분해 승인된 항목만 고친 뒤 같은 기준으로 재검수한다.

## 애드아이티 업무 적용

공공기관 제안서는 RFP 요구사항 추적표 → 통계·정책·사례 원문 대조 → 심사 기준과 실행계획 검토 → 장표 수·용어·표기·개인정보 점검 순서로 검수한다.

## 오늘의 실제 사례

### Morgan Stanley — OpenAI 제공 고객사례

금융 자문용 검색·요약 결과의 정확성·일관성·규제 적합성을 확보하기 위해 실제 업무 사례로 평가 세트를 만들었다. 자문역과 프롬프트 엔지니어가 정확성·일관성을 채점하고, 다양한 회의 유형에서 핵심 조치를 오류 없이 잡는지 검사했으며, 표본 질문 회귀 테스트를 매일 수행했다. OpenAI 고객사례에서 자산관리 자문팀 사용률 98% 이상, 검색 가능한 문서 접근 범위 20%에서 80%로 확대됐다고 보고했다. 이는 당사자 제공 수치이며 독립 평가는 아니다.

원문: https://openai.com/index/morgan-stanley/

### 국내 공개 사례

공공 디지털서비스 자료에 따르면 기획재정부는 2025년 2월부터 약 1,000명의 내부 구성원에게 자료 검색·질의응답·보고서 초안 기능을 제공했다. 검수 절차와 품질 성과 수치는 공개 자료에서 확인되지 않았다.

원문: https://www.digitalmarket.kr/web/board/BD_board.view.do?bbsCd=1030&bbscttSeq=20251001172836143&domainCd=2

## 2분 따라 하기

1. 실제 제안서·보도자료·콘텐츠 한 페이지를 고른다.
2. 원 요청의 필수 조건 세 개와 근거 자료를 붙인다.
3. 결함 로그만 만들고 치명도 순으로 정렬한다.
4. 가장 위험한 결함 하나를 고친 뒤 같은 기준으로 재검수한다.

## 복사형 실전 프롬프트

~~~text
[검수 대상]
{제안서·보도자료·콘텐츠 원문}

[원 요청과 완료 기준]
{목적·대상·필수 항목·제약·형식}

[근거 자료]
{RFP·정책자료·통계 원문·승인된 참고자료}

지금은 수정본을 쓰지 말고 아래 4단계로 검수하라.
1. 요구 일치
2. 근거 검증
3. 논리·실행성
4. 형식·표현

| 심각도 | 검수 단계 | 정확한 위치 | 발견 결함 | 판단 근거 | 권장 수정 | 미해결 질문 |

- 심각도는 치명/중요/경미로 구분
- 확인되지 않으면 ‘미확인’으로 표시
- 자료에 없는 사실·수치·링크를 만들지 말 것
- 결함이 없는 항목도 확인 근거를 남길 것
- 승인 전에는 원문을 다시 쓰지 말 것
~~~

## 결과 체크 3문항

- 모든 결함에 정확한 위치와 판단 근거가 있는가?
- 확인할 수 없는 내용은 ‘미확인’으로 남겼는가?
- 가장 위험한 결함을 수정한 뒤 같은 기준으로 재검수했는가?

## 자주 하는 실수

- 기준 없이 “다시 검토해”라고 요청하기
- 근거 자료 없이 사실 검증까지 맡기기
- 검수와 재작성을 동시에 시키기
- 오탈자만 보고 요구 누락·수치 오류·실행 위험을 놓치기

## 오늘의 미션

실제 제안서 한 페이지에서 치명 결함 1개와 중요 결함 2개를 찾아 결함 로그로 남긴다. 가장 위험한 한 개를 수정하고 같은 네 관문을 다시 통과한다.
