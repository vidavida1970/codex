# DAY 13. 심사표와 평가기준 활용하기

애드아이티 제공 · ChatGPT로 성공하기 · 2026-07-28

## 10초 훅

좋아 보이는 초안보다, 몇 점인지 근거로 설명되는 초안이 더 빨리 개선됩니다.

## 오늘의 학습목표

공공기관 제안 심사표를 가중치·점수 기준·근거가 포함된 루브릭으로 바꾸고, 초안 평가와 재작성을 한 흐름으로 연결한다.

## 핵심 개념 1분

루브릭은 “좋다/나쁘다”를 말하는 표가 아니라 무엇을 얼마나 중요하게 보고, 어떤 증거로 몇 점을 줄지 미리 합의한 평가 계약입니다.

1. 평가항목: 과업 이해·전략성·실행성처럼 서로 겹치지 않게 정의
2. 가중치: 중요도를 반영하고 합계를 100점으로 설정
3. 점수 앵커: 1·3·5점이 각각 어떤 상태인지 관찰 가능한 문장으로 정의
4. 근거: 점수마다 초안의 문장·표·장표 위치 표시
5. 치명 결함: 허위 수치·요구사항 누락처럼 총점과 별도로 탈락 위험 표시

핵심 원칙은 초안을 본 뒤 기준을 바꾸지 않고 같은 루브릭으로 원본과 수정본을 다시 평가하는 것입니다.

## 잘못된 사용법과 개선 예시

잘못된 요청: “심사위원 입장에서 냉정하게 평가하고 최고 수준으로 고쳐줘.”

개선 요청: “항목·가중치·1/3/5점 기준으로 채점하라. 점수마다 근거 문장을 표시하고, 가장 낮은 두 항목만 수정한 뒤 같은 표로 재채점하라.”

## 애드아이티 실무 사례

공공기관 제안서의 실습용 100점 루브릭:

- 과업 이해 25점
- 전략·차별성 30점
- 실행 가능성 20점
- 확산·성과 15점
- 품질관리 10점

실제 사업 배점이 아닌 훈련용 가상 배점이며, 각 항목에 1·3·5점 상태와 치명 결함을 추가합니다.

## 오늘의 실제 사례

### Morgan Stanley — OpenAI 제공 고객사례

- 문제: 금융 업무에 AI를 배포하기 전 정확성·일관성·신뢰성 검증 필요
- 흐름: 실제 업무 질문과 요약 과제를 평가 데이터로 구성 → 전문가가 정확성·일관성을 평가 → 프롬프트와 검색 방법 개선 → 배포 후 회귀 테스트
- 공개 결과: 자산관리 자문팀의 AI 도구 채택률 98% 이상, 문서 접근 범위 20%에서 80%로 증가
- 주의: Morgan Stanley가 OpenAI 고객사례에서 보고한 수치이며 독립 평가가 아님
- 재현 포인트: 실제 납품물과 전문가 판단을 평가표에 넣고 수정 후 같은 기준으로 반복 검증
- 원문: https://openai.com/index/morgan-stanley/

국내 공공기관 제안·홍보 업무에서 ChatGPT 루브릭 적용 전후를 비교한 검증 가능한 공개 사례는 확인하지 못했습니다.

## 2분 따라 하기

1. 진행 중인 RFP에서 평가항목 4개를 선택
2. 가중치 합계를 100으로 맞추고 1·3·5점 상태 작성
3. 제안서 한 페이지를 채점하고 점수마다 근거 표시
4. 가장 낮은 항목 하나를 수정하고 같은 루브릭으로 재채점

## 복사형 실전 프롬프트

```text
[평가할 결과물]
{제안서·홍보안·기획안 원문}

[평가 목적과 사용처]
- 목적: {예: 제안심사 전 내부 검수}
- 독자/심사자: {대상}

[평가 루브릭]
| 평가항목 | 가중치 | 1점 상태 | 3점 상태 | 5점 상태 | 치명 결함 |

조건:
- 가중치 합계는 100점
- 항목끼리 중복되지 않게 정의
- 점수 기준은 관찰 가능한 행동·내용으로 작성
- 허위 수치, 필수 요구 누락, 출처 불명은 치명 결함으로 표시

[채점 규칙]
1. 결과물에 실제로 있는 내용만 근거로 채점한다.
2. 각 점수 옆에 근거 문장 또는 위치를 표시한다.
3. 근거가 없으면 추정하지 말고 ‘근거 없음’으로 표시한다.
4. 원본을 본 뒤 평가기준이나 가중치를 바꾸지 않는다.

[출력 순서]
1. 확정 루브릭
2. 원본 점수표와 가중 총점
3. 영향도가 큰 결함 3개
4. 가장 낮은 2개 항목의 수정안
5. 같은 루브릭으로 수정본 재채점
6. 점수 변화와 남은 위험
```

## 결과 체크 3문항

- 가중치 합계가 100이고 항목 간 중복이 없는가?
- 모든 점수에 결과물 안의 근거가 표시됐는가?
- 수정 전후에 같은 루브릭을 사용했는가?

## 자주 하는 실수

- 우수·보통·미흡만 적고 차이를 관찰 가능한 문장으로 설명하지 않기
- 유사한 항목을 겹쳐 같은 장점을 두 번 채점하기
- 근거가 없는 항목에도 평균 점수를 주기
- 총점만 보고 치명 결함을 놓치기
- 점수가 낮게 나오자 평가기준을 수정하기

## 오늘의 미션

실제 RFP의 심사 항목으로 100점 루브릭을 만들고 제안서 한 페이지를 채점하세요. 가장 낮은 항목을 수정한 뒤 기준을 바꾸지 않고 10점 이상 개선되는지 확인합니다.
