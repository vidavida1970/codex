# DAY 20. 프롬프트 회귀 테스트로 품질 유지하기

**발행일:** 2026년 8월 6일  
**과정:** ADDIT | ChatGPT로 성공하기 40일 과정

## 10초 훅

프롬프트를 고친 뒤 한 번 좋아 보였다고 바로 배포하나요? 먼저 확인할 것은 새 문장이 아니라 예전에 통과하던 입력이 지금도 통과하는지입니다.

## 오늘의 학습목표

DAY 18 템플릿과 DAY 19 프롬프트 v2를 고정 테스트셋으로 다시 실행하고, 기준별 통과/실패와 회귀 여부를 기록한 회귀 테스트표 v1을 만든다.

## 핵심 개념 1분

회귀 테스트는 새 프롬프트가 더 그럴듯한지 감으로 보는 작업이 아니다. 고정된 대표 입력과 같은 평가표로 v1·v2를 비교해 품질이 유지되는지 확인하는 작업이다.

1. **고정 테스트셋:** 정상 2개, 예외 1개, 누락 1개처럼 바꾸지 않는 입력을 둔다.
2. **평가기준과 통과 조건:** 근거·대상 적합성·형식·금지 표현처럼 합격선을 먼저 적는다.
3. **v1 vs v2 동시 판정:** 같은 입력·같은 기준으로 통과/실패를 표에 기록한다.
4. **회귀·개선·보류:** 기존 통과 케이스가 다시 실패하면 배포하지 않는다.

## 잘못된 사용법과 개선

- BAD: “한 번 더 돌려보니 괜찮아 보여. 이걸로 통일하자.”
- BETTER: 같은 입력 4개와 같은 평가표로 v1·v2를 비교하고, 기존 통과 케이스 중 하나라도 실패하면 수정 후 재시험한다.

## 애드아이티 실무 예시

공공기관 제안서 요약문 템플릿

- 정상: RFP·대상·승인 예시가 모두 있음
- 예외: 수치는 있으나 측정 기간이 없음
- 누락: 대상 정보가 비어 있음
- 통과 조건: 근거 없는 수치 0개, 대상 명시, 500자 구조, 필수값 누락 시 누락표 출력

## 오늘의 실제 사례

OpenAI Cookbook `Building resilient prompts using an evaluation flywheel`은 실패 분석 → 테스트 데이터셋·grader 측정 → 프롬프트 개선 → 재측정의 순환을 권한다. Working with evals 가이드도 모델 출력을 지정한 스타일·내용 기준으로 평가하고 프롬프트를 반복 개선하라고 안내한다.

국내 기업의 프롬프트 회귀 테스트 성과를 수치로 입증한 검증 가능한 원문은 확인하지 못해, 임의의 사례나 성과 수치를 만들지 않았다.

## 2분 따라 하기

1. DAY 18 템플릿 v1과 DAY 19 프롬프트 v2를 준비한다.
2. 정상 2개, 예외 1개, 누락 1개 입력을 고정한다.
3. 평가기준 3~4개와 통과 조건을 적는다.
4. 같은 입력으로 v1·v2를 실행하고 통과/실패를 표로 기록한다.

## 오늘의 미션

애드아이티 업무 템플릿 1개에 대해 고정 테스트셋 4개와 평가기준 3개로 v1·v2 회귀 테스트표를 완성한다. 회귀가 있으면 배포하지 말고 원인 1개만 수정한 뒤 같은 표로 재시험한다.

## 한 줄 정리

좋은 프롬프트 개선은 더 긴 지시문이 아니라, 같은 시험에서 다시 통과하는 지시문이다.
