# DAY 21. 품질 기준을 팀 검수 체크리스트로 전환하기

**발행일:** 2026년 8월 7일  
**과정:** ADDIT | ChatGPT로 성공하기 40일 과정

## 10초 훅

품질 기준이 개인 머릿속에만 있으면 검수마다 결과가 달라집니다. 오늘은 그 기준을 팀이 같이 쓰는 배포 체크리스트로 바꿉니다.

## 오늘의 학습목표

DAY 20의 평가기준·통과 조건·회귀 판정 규칙을 팀 공통 검수 체크리스트 v1으로 전환한다. 항목마다 확인 방법, 통과 기준, 실패 시 조치, 담당을 적고 최종 판정을 배포/보류/재작성 중 하나로 고른다.

## 핵심 개념 1분

팀 검수 체크리스트는 문장이 괜찮아 보이는지 감으로 보는 목록이 아니다. 누가 검수해도 같은 결론이 나오도록 합격선과 조치를 고정한 공통 판정표다.

1. **검수 항목:** 근거, 대상, 형식, 리스크, 행동 가능성처럼 꼭 볼 축을 고른다.
2. **확인 방법과 통과 기준:** 어떻게 보고, 어디까지 합격인지 적는다.
3. **실패 시 조치와 담당:** 보류, 수정 요청, 재작성, 원자료 보완을 누구 책임으로 남긴다.
4. **최종 판정:** 배포 / 보류 / 재작성 중 하나로 결론을 고정한다.

## 잘못된 사용법과 개선

- BAD: “전체적으로 괜찮아 보이면 올리자. 세부 기준은 각자 감각으로.”
- BETTER: 배포 전 공통 체크리스트 5~7개로 확인하고, 하나라도 실패하면 배포하지 않으며 실패 항목·조치·담당을 남긴다.

## 애드아이티 실무 예시

공공기관 제안서 요약문 / SNS 초안 / 주간 브리핑

- 근거: 제공 자료에 없는 수치·인용 0개
- 대상: 핵심 대상과 사용처 명시
- 형식: 지정 분량·구조 준수
- 리스크: 과도한 약속·미확인 성과 금지
- 누락 처리: 필수값 없으면 보류 사유 또는 누락표
- 최종 판정: 배포 / 보류 / 재작성

## 오늘의 실제 사례

OpenAI Cookbook `Building resilient prompts using an evaluation flywheel`은 실패 유형을 라벨링하고 테스트 기준을 고정한 뒤 개선을 재측정하라고 안내한다. Working with evals 가이드도 지정한 스타일·내용 기준으로 출력을 평가하고 반복 개선하라고 설명한다. 팀 검수 체크리스트는 이 평가 기준을 사람이 함께 쓰는 배포 게이트로 옮긴 형태다.

국내 팀의 AI 검수 체크리스트 도입 성과를 수치로 입증한 검증 가능한 원문은 확인하지 못해, 임의의 사례나 성과 수치를 만들지 않았다.

## 2분 따라 하기

1. DAY 20 평가기준 3~4개를 가져온다.
2. 각 기준을 확인 방법 / 통과 기준 / 실패 시 조치 / 담당으로 펼친다.
3. 팀 공통 항목 5~7개로 정리한다.
4. 최근 결과물 1개에 적용해 배포 / 보류 / 재작성을 고른다.

## 오늘의 미션

애드아이티 업무 결과물 1개에 대해 팀 검수 체크리스트 5~7항목을 만든다. 각 항목에 확인 방법·통과 기준·실패 시 조치·담당을 채우고, 실제 초안 1개에 적용해 배포 / 보류 / 재작성 판정까지 남긴다.

## 한 줄 정리

좋은 팀 품질 관리의 출발점은 더 엄격한 취향이 아니라, 같은 결과물에 같은 판정을 남기는 체크리스트다.
