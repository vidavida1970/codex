# DAY 31. Projects로 제안 업무의 공용 작업실 만들기

- 발행일: 2026년 8월 17일
- LEVEL 4
- 핵심 한 문장: Project에는 공용 맥락을, chat에는 하나의 완성물을 둔다.

## 10초 훅
RFP와 브랜드 규칙을 매번 다시 설명한다면, 일을 하는 것이 아니라 맥락을 운반하는 중입니다.

## 오늘의 학습목표
실제 제안 업무 하나를 파일·프로젝트 지침·산출물별 chat으로 구성해 반복 설명 없이 이어가는 공용 작업실을 만든다.

## 핵심 개념 1분
Project는 공용 맥락, chat은 하나의 산출물이다. 업무 범위를 이름에 고정하고 최신 RFP·브랜드 가이드·승인 사례를 sources에 둔다. 근거·금지·출력·검수 기준은 프로젝트 지침에 고정하고, 요구사항표·전략·원고·검수는 별도 chat으로 나눈다.

편성 변경: DAY 30의 다음 예고는 PPT 구조 전환이었지만 LEVEL 4 진입과 2026년 8월 17일 갱신된 OpenAI Projects 안내를 우선 반영했다.

## 잘못된 사용법과 개선
- 잘못: 모든 업무와 구버전 자료를 하나의 chat에 누적한다.
- 개선: Project 하나에 최신 공용 자료와 지침을 두고 chat마다 산출물과 완료 기준을 하나만 부여한다.

## 애드아이티 실무 사례
공공기관 홍보 제안 Project를 `[기관명]_[사업명]_2026`으로 만든다. Sources는 최신 RFP, 확정 사실, 브랜드 가이드, 승인 사례로 나눈다. 프로젝트 지침에는 출처 우선순위·문체·금지·검수 기준을 기록하고 chat은 요구사항표·전략·콘텐츠·검수로 분리한다. 공유 전 개인정보와 비공개 자료의 업로드 권한 및 참여자 접근 수준을 확인한다.

## 오늘의 실제 사례
**RingCentral · 2026년 8월 공개 · OpenAI 제공 고객 사례(당사자 주장)**
프로젝트 상태·회의 기록·도구별 정보가 흩어진 문제를 해결하기 위해 ChatGPT Work가 Jira, Google Sheets, CRM 등의 정보를 바탕으로 상태 보고와 알림을 만들고 회의 전 장애물·담당자·조치를 정리했다. RingCentral은 수동 조정이 줄고 PMO가 더 많은 프로젝트를 정확하게 관리했다고 밝혔으나 독립 검증 가능한 정량 수치는 제시하지 않았다.
- 재현 포인트(강사 해석): 제안 Project에 최신 자료·공통 지침·산출물별 chat을 둔다.
- 원문: https://openai.com/index/ringcentral/
- 국내 사례: Projects 운영 과정을 공개 화면과 출처로 재현할 수 있는 국내 기관 사례는 확인하지 못했다.

## 2분 따라 하기
1. 새 Project 이름을 `[기관명]_[사업명]_2026`으로 만든다.
2. 최신 RFP·브랜드 가이드·승인 사례 3개만 추가한다.
3. 프로젝트 지침을 넣는다.
4. `01_RFP_요구사항표` chat에서 자료 목록과 누락부터 확인한다.

## 복사형 실전 프롬프트
```text
[목적] [기관명]의 [사업명] 제안 업무를 근거 기반으로 완성한다.
[자료] 파일명·기관·기준일·버전·용도를 먼저 표로 정리한다. 최신 버전만 쓰고 충돌·구버전·누락은 작업 전에 보고한다. 중요한 주장과 수치는 파일명과 페이지·표·행 위치를 붙인다. 없는 사실·수치·사례를 만들지 않는다.
[작업] 사실·추론·제안을 구분한다. chat마다 하나의 산출물과 완료 기준을 먼저 확인한다. 정보가 부족하면 확인 질문 목록을 만든다.
[첫 작업] 현재 Project sources의 자료 인벤토리와 위험·누락을 먼저 보여줘.
```

## 결과 체크 3문항
1. 최신·승인 자료만 있고 기준일이 보이는가?
2. 지침에 근거·금지·출력·검수 규칙이 있는가?
3. 각 chat이 하나의 산출물과 완료 기준만 다루는가?

## 자주 하는 실수
구버전과 최신 파일을 함께 올리기, 여러 기관·사업 섞기, 한 chat에 모든 산출물 만들기, 공유 전 자료 권한을 확인하지 않기.

## 오늘의 미션
진행 중인 제안 업무 하나로 Project 1개·최신 자료 3개·프로젝트 지침 8줄·산출물 chat 1개를 만들고 자료 인벤토리 5행을 완성한다.
