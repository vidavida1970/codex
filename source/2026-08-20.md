# DAY 32 — 메모리와 프로젝트 지침을 구분해서 쓰기

- 발행일: 2026-08-20
- LEVEL 4 · Projects·메모리·업무 통합
- 핵심 한 문장: 기억은 이어갈 맥락, 지침은 지켜야 할 계약입니다.

## 10초 훅

“우리 문체를 기억해”와 “이 사업에서는 이 규칙을 지켜”는 저장할 위치가 다릅니다.

## 학습목표

개인 메모리·project-only memory·프로젝트 지침을 구분해 제안 업무의 맥락은 이어가고, 사업별 규칙은 섞이지 않게 설계합니다.

## 핵심 개념

- 개인 메모리: 답변 언어·상시 선호처럼 여러 대화에 오래 적용할 정보
- Project-only memory: 같은 Project 안의 대화 맥락만 활용하고 바깥 대화와 분리
- 프로젝트 지침: 출처 우선순위·문체·금지사항·출력 형식·검수 기준처럼 반드시 지킬 규칙
- Project sources: RFP·브랜드 가이드·승인본처럼 원문으로 검증할 자료

판단 공식: 여러 업무에 계속 적용하면 개인 메모리, 이 사업의 과거 대화라면 Project 맥락, 반드시 지킬 규칙이면 프로젝트 지침, 사실 확인 자료라면 Project source에 둡니다.

## 잘못된 사용법과 개선

- 잘못된 사용: 민감한 사업 규칙을 개인 메모리에 저장해 다른 업무까지 영향을 줌
- 개선: 사업별 Project를 분리하고, 규칙은 프로젝트 지침에, 대화의 연속성은 project-only memory에 둠

## 애드아이티 실무 예시

| 정보 | 둘 위치 | 이유 |
|---|---|---|
| 항상 한국어, 결론 먼저 | 개인 메모리 또는 사용자 설정 | 여러 업무에 공통 |
| A기관 RFP 평가항목 | Project source | 원문 확인이 필요한 사실 |
| A기관은 수치를 표로 제시 | 프로젝트 지침 | 해당 사업의 명시 규칙 |
| 전략회의에서 폐기한 1안 | Project 안의 chat | 이 사업의 진행 맥락 |
| 다른 기관의 비공개 자료 | 넣지 않음 | 권한·목적 범위 밖 |

## 오늘의 실제 사례

검증 가능한 실제 도입 사례는 확인하지 못해 OpenAI의 공개 워크플로로 대체했습니다.

- 기관: OpenAI
- 공개 시점: 2026-08-20 확인
- 문제: 분기 계획의 파일·대화·지침이 흩어져 팀원이 같은 맥락에서 이어서 일하기 어려움
- 흐름: 공유 Project에 자료와 대화를 모으고 project-only memory로 외부 개인 메모리와 분리
- 확인된 결과: OpenAI는 팀 정렬·온보딩·지식 축적을 위한 live context hub 예시로 안내하며, 독립 검증된 성과 수치는 공개하지 않음
- 재현 포인트: 기관별 제안을 서로 다른 Project로 나누고 각 Project의 지침·자료·대화만 사용
- 원문: [Projects in ChatGPT](https://help.openai.com/en/articles/10169521-projects-in-chatgpt)

## 내 업무 적용 포인트

“기억해”라고 쓰기 전에 정보가 계정 전체·이 Project·작업 규칙·근거 자료 중 어디에 속하는지 먼저 결정합니다.

## 2분 따라 하기

1. 진행 중인 제안 Project의 Project settings를 엽니다.
2. 사업 맥락을 다른 대화와 분리해야 한다면 Project-only memory를 선택합니다.
3. 프로젝트 지침에 근거·문체·금지·출력·검수 기준을 5줄로 씁니다.
4. 아래 프롬프트로 현재 정보의 저장 위치를 점검합니다.

## 복사형 실전 프롬프트

```text
이 Project의 현재 정보와 규칙을 다음 4가지로 분류해줘.

1. 개인 메모리 후보: 여러 업무에 오래 적용할 선호
2. Project 맥락: 이 사업의 대화에서만 이어갈 정보
3. 프로젝트 지침: 반드시 지켜야 할 명시 규칙
4. Project source: 원문으로 확인해야 할 근거 자료

각 항목을 [내용 / 위치 / 이유 / 위험 / 조치] 표로 작성해.

검수 규칙:
- 개인정보·다른 기관의 비공개 정보는 저장 후보에서 제외
- 사실과 작업 규칙을 섞지 않기
- 오래된 내용은 기준일과 확인 필요 표시
- 확실하지 않은 내용은 임의로 기억시키지 말고 질문으로 남기기

마지막에 지금 바로 옮기거나 삭제할 항목 3개를 우선순위로 제안해.
```

## 결과 체크 3문항

1. 계정 전반의 선호와 사업 전용 정보가 분리됐는가?
2. 프로젝트 지침이 기억에 맡기지 않고 문장으로 명시됐는가?
3. 개인정보·다른 기관 자료·오래된 사실의 위험을 확인했는가?

## 자주 하는 실수

- 모든 규칙을 “기억해” 한마디로 처리
- project-only memory를 보안·권한 검토의 대체물로 해석
- Project memory에 별도 목록이 있다고 가정
- 설정 변경이 즉시 반영된다고 생각

## 최신 업데이트

2026-08-14, OpenAI는 적격한 비공유 Project에서 생성 후에도 Default memory와 Project-only memory를 변경할 수 있다고 안내했습니다. 공유 Project는 project-only memory로 유지되며 변경 반영에는 몇 시간이 걸릴 수 있습니다.

- 사실: [ChatGPT Release Notes](https://help.openai.com/en/articles/6825453-chatgpt-release-notes)
- 실무 해석: 기존 기관별 Project도 새로 만들지 않고 정보 경계를 재설계할 수 있음
- 강사 제안: 변경 뒤 테스트 chat으로 다른 Project의 정보가 섞이지 않는지 확인하고 민감자료는 별도 권한·보안 기준으로 관리
