# DAY 34 — Work에서 승인 지점이 있는 실행계획 만들기

발행일: 2026년 8월 26일

## 핵심

앱이 연결된 Work에서는 “해줘”보다 “어디까지 읽고, 어디서 멈추고, 무엇은 승인 후 실행할지”를 먼저 정해야 합니다. 실행계획은 SCOPE → READ → DRAFT → REVIEW → ACT → LOG 순서로 나누고, 외부에 영향을 주는 행동은 승인 지점으로 고정합니다.

## 공식 근거

- OpenAI Help Center, Apps in ChatGPT: 앱은 외부 도구·정보·행동에 연결되며, 기본적으로 Important actions 설정은 읽기는 자동으로 허용할 수 있지만 외부 영향·민감 정보·되돌리기 어려운 행동 전에는 확인을 요구합니다.
- OpenAI Help Center, Workspace Agents: Workspace Agents는 반복 업무를 위한 에이전트를 만들 수 있고, 앱·도구 연결 및 공유·스케줄 실행을 지원합니다.

## 5분 강의 원고

앱을 연결하면 업무 속도는 빨라집니다. 하지만 속도가 빨라질수록 먼저 정해야 할 것이 있습니다. 바로 승인 지점입니다.

가장 위험한 방식은 “자료 읽고, 메일 보내고, 일정 잡고, 파일도 정리해줘”처럼 읽기와 실행을 한 문장에 섞는 것입니다. 이렇게 요청하면 초안 작성, 외부 발송, 파일 이동, 권한 변경이 한 흐름 안에 들어갑니다.

DAY 34의 기준은 단순합니다.

1. SCOPE에서 읽을 자료와 제외할 자료를 정합니다.
2. READ에서는 자동으로 읽어도 되는 작업만 둡니다.
3. DRAFT에서는 외부 영향이 없는 초안만 만듭니다.
4. REVIEW에서는 사람이 확인할 체크포인트를 둡니다.
5. ACT에서는 승인 후에만 외부 행동을 실행합니다.
6. LOG에서는 무엇을 읽고 무엇을 바꾸었는지 남깁니다.

이 흐름을 쓰면 ChatGPT를 막는 것이 아니라, 더 믿고 맡길 수 있는 구조를 만드는 것입니다.

## 복사형 실전 프롬프트

```text
너는 Work 실행계획 검수자다.

업무 목표: {무엇을 끝낼지}
연결 앱: {Drive, Gmail, Calendar, GitHub 등}
허용 자료: {읽어도 되는 폴더·문서·기간}
허용 행동: {초안 작성, 요약, 일정 후보 작성 등}
금지 행동: {발송, 삭제, 권한 변경, 외부 공유 등}
승인자: {최종 확인할 사람}
완료 기준: {검수 가능한 산출물}

SCOPE, READ, DRAFT, REVIEW, ACT, LOG 단계로 실행계획을 작성해줘.
각 단계마다 위험도, 승인 필요 여부, 중단 조건을 붙여줘.
승인 없이 메일 발송·파일 삭제·권한 변경·외부 공유를 실행하지 마.
```

## 오늘의 미션

연결 앱이 들어가는 업무 하나를 골라 SCOPE → READ → DRAFT → REVIEW → ACT → LOG 실행계획을 작성하고, 승인 없이 실행하면 안 되는 행동 3개를 표시하세요.
